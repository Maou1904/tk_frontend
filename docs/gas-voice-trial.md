# ทดลองพูดรับออร์เดอร์เฉพาะหน้าแก๊ส

เปิดหน้า **ขายแก๊ส** แล้วกด **แตะเพื่อพูด** เช่น:

- “เอ่อ ส่งแก๊สถังใหญ่ บ้านคุณสมชายปตท.”
- “ส่งแก๊ส สยาม ถังเล็ก สองถัง บ้านป้าสมศรี หลังวัด”
- “ส่งแก๊ส ปตท สิบห้าโล 2 ถัง ลูกค้าคุณสมชาย ที่อยู่บ้านเลขที่ 12/3”
- “ปตท ถังใหญ่ 2 ถัง ถังเล็ก 1 ถัง ส่งที่หลังวัด”
- “ปตท ถังใหญ่กับถังเล็กอย่างละ 2 ถัง ลูกค้าคุณสมชาย ส่งที่อู่ช่างชัย”
- “ส่งปตทถังใหญ่ 1 ถังให้คุณเจเจที่ดอนภูตา”

เมื่อบริการเสียงส่งข้อความสมบูรณ์ ระบบจะกรอกฟอร์มและเปิดขั้นรายละเอียด
ตรวจยี่ห้อ ขนาด จำนวน ชื่อ จุดส่ง และคนส่ง แล้วกด **ทำรายการแก๊ส** เอง
ปุ่ม **พูดเสร็จแล้ว** หยุดรับเสียงและรอข้อความ ส่วน **ยกเลิกการฟัง** ไม่เปลี่ยนฟอร์ม

ถังใหญ่หมายถึง 15 กก. ถังเล็กหมายถึง 4 กก. รองรับหลายขนาดในยี่ห้อเดียวในหนึ่งประโยค
จำนวนผูกกับแต่ละขนาด หากไม่บอกจำนวนของขนาดไหนใช้ 1 ถังสำหรับขนาดนั้นและแจ้งในผลลัพธ์
คำว่า “อย่างละ 2 ถัง” ใช้จำนวน 2 กับทุกขนาดที่บอก
ข้อมูลสินค้าต้องตรงกับยี่ห้อและขนาดในสต็อกจริง หากไม่พบ มีสินค้าซ้ำ หรือคงเหลือไม่พอ จะไม่เปลี่ยนฟอร์ม
ตรวจครบทุกขนาดก่อนกรอก หากขนาดใดไม่ผ่านจะไม่เปลี่ยนทั้งออร์เดอร์
ถ้าบอกหลายยี่ห้อ ต้องแยกทำรายการตามยี่ห้อ หากบอกขนาดเดิมซ้ำให้รวมจำนวนก่อนพูดใหม่
ประโยคใหม่จะแทนที่ถังที่เลือกไว้ ส่วนการบอกจุดส่งใหม่จะไม่ดึงชื่อหรือเบอร์ลูกค้าคนก่อนมาปะปน
ชื่อบ้านเก็บตามที่พูด เช่น “บ้านคุณสมชาย” ไม่ค้นหรือเดาบ้านเลขที่เพิ่มเติม
ถ้าบอกสถานที่อย่างเดียว เช่น “ส่งที่หลังวัด” จะกรอก “หลังวัด” ทั้งชื่อและจุดส่ง
ถ้าบอกชื่อลูกค้าแยกจะใช้ชื่อนั้น หากออร์เดอร์ใหม่ไม่บอกทั้งชื่อและจุดส่งจะเว้นสองช่องและเบอร์โทรไว้
การจ่ายเงิน คนส่ง ค่าส่ง และการคืนถังยังตรวจจากช่องในฟอร์มเดิม; การเลือกถังด้วยเสียงเริ่มถังคืนที่ 0

ตัวทดลองใช้ `SpeechRecognition` / `webkitSpeechRecognition` ภาษา `th-TH` ตามด้วยตัวแยกข้อความ
เมื่อคอมที่เชื่อมกับร้านเปิดและโมเดลพร้อม แถบ “AI ในคอม” จะแสดงและใช้โมเดลในคอมแยกข้อความ
เมื่อคอมปิด เน็ตหลุด หรือโมเดลไม่พร้อม จะใช้ตัวแยกคำพื้นฐาน และเชื่อมกลับอัตโนมัติเมื่อพร้อม
หน้าแก๊สตรวจสถานะทุก 3 วินาทีขณะเปิดอยู่ โดยไม่ต้องรีเฟรชและไม่ล้างข้อความที่กำลังพิมพ์
ระบบยกเลิกคำขอที่ช้าแล้วใช้ rules แทน ไม่ส่งข้อความไป Cloudflare
กุญแจลับของคอมเก็บเฉพาะในคอม เว็บและ Render ใช้เพียงกุญแจสาธารณะเพื่อตรวจสอบผู้รับงาน และไม่มีการฝึกโมเดลเอง
บริการเสียงของเบราว์เซอร์อาจต้องใช้อินเทอร์เน็ตและส่งเสียงไปยังผู้ให้บริการ
แอปไม่อัดหรือเก็บไฟล์เสียง และฟังเฉพาะเมื่อกดปุ่ม โดยหยุดเมื่อออกจากหน้า/ซ่อนแท็บ
ต้องทดสอบการรองรับภาษาไทย สิทธิ์ไมค์ และเสียงรบกวนบน iPad ที่ร้านจริง
บนอุปกรณ์อื่นที่เปิดผ่าน LAN ต้องใช้ HTTPS เพื่อเข้าถึงไมค์
หากปุ่มเสียงไม่รองรับ ให้ใช้ไมค์บนคีย์บอร์ดในช่องข้อความ แล้วกด **กรอกฟอร์มจากข้อความ**

## การตรวจสอบ

```powershell
npm run build
node --experimental-strip-types --test src/gasVoice.test.mjs
```

ทดสอบเบราว์เซอร์ด้วย Playwright ที่ติดตั้งไว้และ dev server ที่เปิดอยู่:

```powershell
node scripts/test-gas-voice-browser.mjs
```

ตั้ง `PLAYWRIGHT_MODULE` เป็นพาธ module entry ได้หาก Playwright อยู่ภายนอกโปรเจกต์
ตั้ง `PLAYWRIGHT_CHANNEL=chrome` เพื่อใช้ Chrome ที่ติดตั้งอยู่
ตั้ง `GAS_VOICE_ARTIFACT_DIR` เพื่อบันทึกภาพหน้าจอ
การทดสอบใช้ API และเหตุการณ์รู้จำเสียงจำลอง ไม่เชื่อมฐานข้อมูลจริง ไม่สร้างบิล และไม่ยืนยันความแม่นยำของเสียงจริง

## เชื่อม AI ในคอมกับร้าน

ดูขั้นตอนตั้งคอม กุญแจตรวจสอบ และเปิดอัตโนมัติที่ `tk_backend/LOCAL-GAS-AI.md`
เว็บจริงใช้โมเดล Qwen3 4B ผ่านโปรแกรมรับงานในคอม โดยคอมเป็นฝ่ายเชื่อมออกไปหา backend
ไม่มีพอร์ตเข้าคอมจากอินเทอร์เน็ต และไม่ใช้บริการโมเดล Cloudflare

backend รับสัญญาณทุก 2.5 วินาที และถือว่าคอมไม่พร้อมเมื่อขาดสัญญาณ 7.5 วินาที
คำขอที่กำลังรอใช้เวลาไม่เกิน 4.5 วินาที แล้วเว็บใช้ rules แทน หน้าแก๊สตรวจสถานะทุก 3 วินาที
เมื่อคอมกลับมาพร้อมจะใช้ AI ได้โดยไม่รีเฟรชและไม่ล้างข้อความในช่อง

ชื่อ จุดส่ง และผลลัพธ์ต้องผ่านตัวตรวจสอบเดิม สินค้าต้องตรงกับสต็อกจริงก่อนเปลี่ยนฟอร์ม
ไม่บันทึกข้อความออร์เดอร์หรือคำตอบโมเดลลง log หรือฐานข้อมูลของตัวช่วย AI
จำกัด 20 คำขอต่อคนต่อนาทีและพร้อมกันไม่เกิน 2 คำขอ ไม่มีโควต้า cloud รายวัน
โมเดลในคอมต้องพร้อมจริงก่อนแจ้งออนไลน์ การโหลดโมเดลหลังเปิดคอมอาจใช้เวลาสักครู่
